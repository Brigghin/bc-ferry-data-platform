# BC Ferry Data Platform API

A FastAPI service that retrieves and serves BC Ferries sailing schedules.

## Requirements

- Python 3.14
- [uv](https://docs.astral.sh/uv/)

The `.python-version` file selects Python 3.14 for local development. The `uv.lock` file pins the resolved dependency versions.

## Run locally

From the `backend` directory, install the project dependencies and start the development server:

```powershell
uv sync --locked
uv run fastapi dev
```

The API is available at <http://127.0.0.1:8000>. Interactive API documentation is at <http://127.0.0.1:8000/docs>.

## Endpoint

### `GET /version/`

Returns the installed backend package version.

Example response:

```json
{
	"version": "0.1.0"
}
```

### `GET /ferries/`

Returns stored capacity-feed routes and sailings from today onward. Add the optional `route_code` query parameter to filter by route; hyphens and letter case are normalized.

Example response:

```json
[
	{
		"routeCode": "TSASWB",
		"fromTerminalCode": "TSA",
		"toTerminalCode": "SWB",
		"sailingDuration": "1h 35m",
		"sailings": [
			{
				"serviceDate": "2026-11-10",
				"scheduledTime": "2026-11-10T08:30:00-08:00",
				"actualDepartureTime": null,
				"actualArrivalTime": null,
				"capacityKnown": true,
				"carCapacityKnown": true,
				"oversizeCapacityKnown": true,
				"fill": 50,
				"carFill": 60,
				"oversizeFill": 70,
				"vesselName": "Example vessel",
				"status": "scheduled",
				"observedAt": null,
				"APICapturedAt": "2026-11-10T15:00:00+00:00"
			}
		]
	}
]
```

### `POST /ferries/refresh`

Fetches the current capacity feed from the upstream API, stores route/sailing data, and returns the number of routes processed. A refresh updates the existing record for the same route, service date, and scheduled time, or inserts a new sailing. A sailing without a scheduled time fails the refresh. Previously known actual times are retained if absent in a later feed; fill values are retained when their corresponding capacity-known flag is false.

### Automatic refresh

The existing refresh endpoint can be called by an external scheduler every 10 minutes; no separate refresh command is required. Configure the scheduled job with your hosting provider once you have chosen one. The schedule is not enabled by this repository. For example, a scheduler that supports cron and shell commands can use:

```cron
*/10 * * * * curl --fail --silent --show-error --request POST https://YOUR-BACKEND-HOST/ferries/refresh
```

Replace the URL with your backend address. The endpoint currently has no authentication; protect it before exposing it publicly or scheduling remote requests. Configure your scheduler to report failed requests. Concurrent refreshes can conflict; failed refreshes should be retried by the scheduler.

## Data source and storage

The refresh endpoint reads the capacity feed from the [BC Ferries API](https://www.bcferriesapi.ca/v2/). `GET /ferries/` serves data from the configured database. The autogenerated capacity-schema migration drops legacy columns and adds required columns without defaults. It is intended for empty ferry tables and will fail on existing rows; review and adapt it before upgrading a database with data. Run the Alembic upgrade before refreshing.
