# BC Ferry Data Platform API

A FastAPI service that retrieves and serves BC Ferries sailing schedules.

## Requirements

- Python 3.11 or newer (`requires-python = ">=3.11"`)
- [uv](https://docs.astral.sh/uv/)

The `.python-version` file selects Python 3.11 for local development; the repository `Dockerfile` builds the deployed image on a newer Python. The `uv.lock` file pins the resolved dependency versions.

## Run locally

From the `backend` directory, install the project dependencies and start the development server:

```sh
uv sync --locked
uv run fastapi dev
```

The API is available at <http://127.0.0.1:8000>. Interactive API documentation is at <http://127.0.0.1:8000/docs>.

### Database configuration

Set `DATABASE_URL` in the environment or use the repository-root `.env.local` generated by `neon deploy`. Environment variables take precedence over `.env.local`. The Neon file contains credentials and must not be committed. Standard `postgresql://` Neon URLs use the installed psycopg driver automatically.

Neon's `DATABASE_URL` is pooled for application queries. Use its direct `DATABASE_URL_UNPOOLED` for Alembic migrations. For example, from `backend`, temporarily select the direct URL without displaying it.

sh:

```sh
DATABASE_URL=$(uv run python -c "from dotenv import dotenv_values; from pathlib import Path; print(dotenv_values(Path('..') / '.env.local')['DATABASE_URL_UNPOOLED'])") uv run alembic upgrade head
```

PowerShell:

```powershell
$env:DATABASE_URL = uv run python -c "from dotenv import dotenv_values; from pathlib import Path; print(dotenv_values(Path('..') / '.env.local')['DATABASE_URL_UNPOOLED'])"
uv run alembic upgrade head
Remove-Item Env:DATABASE_URL
```

Only run migrations against a database you intend to change. Test them on an isolated branch first; the capacity-schema migration described below is destructive and unsuitable for populated legacy tables as written.

## Endpoint

### `GET /version/`

Returns the installed backend package version.

Example response:

```json
{
	"version": "2.5.0"
}
```

### `GET /ferries/`

Returns stored capacity-feed routes and sailings from today onward. Add the optional `route_code` query parameter to filter by route; hyphens and letter case are normalized.

Example response:

```json
[
	{
		"routeCode": "TSASWB",
		"fromTerminalCode": "TSA",
		"toTerminalCode": "SWB",
		"sailingDuration": "1h 35m",
		"sailings": [
			{
				"serviceDate": "2026-11-10",
				"scheduledTime": "2026-11-10T16:30:00Z",
				"actualDepartureTime": null,
				"actualArrivalTime": null,
				"capacityKnown": true,
				"carCapacityKnown": true,
				"oversizeCapacityKnown": true,
				"fill": 50,
				"carFill": 60,
				"oversizeFill": 70,
				"vesselName": "Example vessel",
				"status": "scheduled",
				"observedAt": "2026-11-10T14:58:00Z",
				"APICapturedAt": "2026-11-10T15:00:00Z"
			}
		]
	}
]
```

### `POST /ferries/refresh`

Fetches the current capacity feed from the upstream API, stores route/sailing data, and returns the number of routes processed. A refresh updates the existing record for the same route, service date, and scheduled time, or inserts a new sailing. A sailing without a scheduled time is skipped and logged. Requests must send an `X-Refresh-Token` header matching the backend's `REFRESH_TOKEN` environment variable; if `REFRESH_TOKEN` is unset, every refresh is rejected with 401. Previously known actual times are retained if absent in a later feed; fill values are retained when their corresponding capacity-known flag is false.

### Automatic refresh

The 10-minute schedule runs on [cron-job.org](https://cron-job.org), which sends `POST https://bc-ferry-data-platform.onrender.com/ferries/refresh` with the `X-Refresh-Token` header. The backend is on Render's free tier, so it sleeps when idle; a cold start can occasionally exceed cron-job.org's 30 second timeout and show up as a failed run.

The [refresh workflow](../.github/workflows/refresh-ferries.yaml) is manual-only (`workflow_dispatch`); start it from the Actions tab. It reads the `FERRY_REFRESH_URL` repository variable (the full endpoint URL) and the `FERRY_REFRESH_TOKEN` repository secret, and it prevents its own runs from overlapping.

To rotate the token, generate a new one:

```sh
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

Then update all three places with the same value: `REFRESH_TOKEN` on Render, the `X-Refresh-Token` header on the cron-job.org job, and the `FERRY_REFRESH_TOKEN` GitHub secret.

### Upstream data quirks

Swartz Bay departures (for example SWB to TSA) stay `departed` and never get an `actualArrivalTime`. The frontend estimates their arrival from the route's `sailingDuration`.

## Data source and storage

The refresh endpoint reads the capacity feed from the [BC Ferries API](https://www.bcferriesapi.ca/v2/). `GET /ferries/` serves data from the configured database. The autogenerated capacity-schema migration drops legacy columns and adds required columns without defaults. It is intended for empty ferry tables and will fail on existing rows; review and adapt it before upgrading a database with data. Run the Alembic upgrade before refreshing.
